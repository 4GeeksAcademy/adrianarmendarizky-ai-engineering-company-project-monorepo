# Brasaland Incidents API

FastAPI backend for the after-sales incident analysis feature (Milestone: Incident File Analysis).

It reuses the exact same validation and metrics logic as `scripts/analyze.py` — see
`app/incidents/controller.py` for how it imports that module directly instead of
duplicating any of its rules.

## Endpoints

- `POST /api/incidents/analyze` — multipart/form-data upload, field name `file`. Returns the
  same summary the script prints, as JSON. Returns `400` if the file is empty or can't be read
  as CSV data.
- `GET /api/incidents/results/export` — returns the most recent analysis as a downloadable
  `results.csv`. Returns `404` if nothing has been analyzed yet in this server session.

## Running it locally

From inside `services/api/`:

```bash
python -m venv venv
source venv/bin/activate        # on Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

The API will be available at `http://localhost:8000`. Interactive docs (auto-generated by
FastAPI) are at `http://localhost:8000/docs` — useful for testing the upload endpoint without
the frontend.

## Running in GitHub Codespaces

The API itself doesn't need any change to run — but if the `uis/incidents` frontend is
accessed via a forwarded Codespaces URL (`https://...app.github.dev`) rather than
`localhost:3000`, the browser will send that URL as its request origin. `app/main.py`
already allows any `*.app.github.dev` origin via a regex, so no CORS changes should be
needed — just make sure port 8000 is forwarded (check the Ports tab) and set to at least
the visibility your frontend needs to reach it.

## Notes

- No database yet: the last analysis is kept in memory (a Python variable) and resets if the
  server restarts. That's intentional for this milestone — same as the in-memory task list in
  the voice command API project.
